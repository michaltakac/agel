## What is and is not verified

The kernel binary above is an unmodified seL4 release. Agel adds no kernel
objects, no syscalls, and no patches; the Agel contract is answered by an
ordinary unprivileged server.

**This is not a verified configuration.** Every Microkit board ships an MCS
kernel, and seL4's verified-configurations table lists MCS proofs as ongoing
rather than complete on every architecture; this board additionally enables
hypervisor support, which is a further configuration outside the AArch64
proofs. Running on an unmodified verified *kernel implementation* is not
the same as running a *verified configuration*, and this spike does the
former.

Nothing here is a claim about the correctness of the Agel code above the
kernel. The system description grants the authority; the protection domains
are ordinary Rust; neither has been verified by anyone.
